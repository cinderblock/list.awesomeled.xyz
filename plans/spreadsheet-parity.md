# Spreadsheet parity audit (workstream 1)

## Goal

Prove that list.awesomeled.xyz holds everything the original Google Sheet
holds, so the sheet can be retired. For every tab: map every column to a YAML
field (or record why it is intentionally dropped), diff every row against
`database/<category>/`, find sheet values (incl. cell notes, comments,
hyperlinks, highlight flags) missing or different in YAML, migrate what's
missing (conflicts resolved by research, not by trusting either side), port
the sheet's README tab into the site's About page, and finish with a concrete
"ready to retire the sheet" checklist.

Parent plan: [website-buildout.md](website-buildout.md). Generated detail:
[spreadsheet-parity/report.md](spreadsheet-parity/report.md) (column mapping
per tab + every open difference, regenerated by `bun run sheet-parity`).

## The tool: `bun run sheet-parity`

`scripts/sheet-parity/` (committed in `7be2178`):

- `xlsx.ts` reads the XLSX export (values, formulas, hyperlinks, notes, solid
  fills, number formats); `load.ts` loads it + the YAML; `match.ts` pairs rows
  with entries (aliases → same name → shared product URL, scored by how much
  of the row's content the entry holds, so duplicate/mislabeled/vandalized
  rows land on the right entry or show up as unmatched).
- `columns.ts` is the column mapping (sheet column → YAML path(s) + how to
  compare); `compare.ts` compares a cell (mapped field first, then anywhere
  site-visible, then YAML comments only).
- `history.ts` adds origin: **sheet edited after import** (baseline CSV
  differs), **YAML revised after import** (value was in the import, research
  commits since), **dropped by a later bulk migration** (value was in the
  import, only IGNORED_COMMITS since), **lost in CSV conversion** (CSV
  carries no notes/links and prints numbers at format precision).
- `acks.yaml`: reviewed differences, keyed `<tab> | <row name> | <column>`
  and pinned to the sheet value, so a later sheet edit resurfaces.
- Output: `plans/spreadsheet-parity/report.md` (+ `--json`). Local snapshot
  mode: `--xlsx <file> --csv-dir <dir>`.

## Decisions already made (don't re-ask)

- Row parity was assumed roughly reached (parent plan); the audit shows it
  isn't quite (see Findings): rows that collided on slug or name were merged.
- Read-only on the sheet; fetch via public export.
- Keep structural commits separate from per-entry data commits; batch commits
  that don't review row data go into `IGNORED_COMMITS` (CLAUDE.md). Bulk
  sheet→YAML migrations (links, notes, precision) are not reviews → ignored.
  Research-verified fixes are reviews → not ignored.
- Sheet-derived prices get no `price_source` (we don't know when they were
  read; inventing a date would be false provenance). Stream 6 owns re-pricing.
- Other workstreams own: DB standardization (2), designer (3), cross-links (4),
  images/datasheets (5), prices/link health (6), browse UX (7). Cross-cutting
  bugs go to `ISSUES.md`.

## Sheet conventions (from its README tab)

- Cell highlight legend: purple `#D9D2E9` = "needs to be verified";
  light yellow `#FFF2CC` = "likely missing data that should be easy to fill in".
  Other fills seen: Pixels `#00FF00` (25), Pixel ICs `#00FFFF` (24), Adapters
  `#4A86E8` (16), Pixel Decoders `#0000FF`/`#E8F0FE` (17 each) — meaning
  unknown, to check.
- Numeric columns hold bare numbers; units come from custom number formats
  (e.g. `0V`, `0.0"mA"`, `[>=1000]0.0,"kHz";0"Hz"`, PD price
  `$0;"FOSS";"Free";@` = -1 FOSS / 0 Free).
- Cell _Notes_ carry per-cell extra info; the _Notes column_ is for high-level
  notes; _Comments_ are for contentious changes.
- Foreign prices are `GOOGLEFINANCE` formulas; the export shows the original
  amount: ELM 70 GBP, MadMapper 359 EUR, Mapio Pro 200 EUR, Resolume 299 EUR,
  Pixie 35 GBP, NetPixel-One 200 GBP, Pixelator 1408 GBP.

### Rows the conversion merged or lost (row parity)

The CSV→YAML conversion keyed entries by slug, so rows with the same or
colliding names were merged (one overwrote the other), and one blank-name row
was skipped:

- Pattern Drivers: two rows named "Jinx!" — `jinx.yaml` holds the **Glediator**
  row's data (Solderlab.de, Glediator mirror URL); the real Jinx! row
  (live-leds.de; Art-Net/sACN/DMX, video/audio in) is missing. "LED Lab"
  (Christopher Schardt, iOS) had a blank name at import and was skipped.
- Controllers: two rows named "Falcon F4V3" — `falcon-f4v3.yaml` holds the
  second row, which is really the **F16V3** (48 outputs, 16320 px, 36 V,
  URL `48-f16v3.html`); the real F4V3 data is missing. Two rows named
  "M8 Port Pixel" — the second is an **ENTTEC DIN-rail pixel controller**
  (2 outputs, 680×2 px, $400, discontinued) never imported.
- Pixels: two rows named "SK6812" — the second is a **CW/WW/Amber (WWA)**
  variant (Hida LC8812B link) never imported.
- Pixel ICs: two rows named "UCS2904" (PWM 1800 vs 1200; second one links
  Advatek's SM16704 page) — identity to research.
- Pixel Decoders: three "WS2811 MosFet Driver" rows — the Eagle Decorations /
  Tindie (Eric Gunnerson) one is missing.
- DIY MicroBoards: **Teensy 2.0** (vs Teensy++ 2.0) and **Raspberry Pi 3
  Model B** (vs B+) missing; slugs `teensy-2-0` and `raspberry-pi-3-model-b`
  are held by the ++ and B+ boards. All "+" slugs dropped the plus.
- Adapters: two "QuinLED-Dig-Uno" rows (newer 2-ch board vs 2018 hardware
  guide row) — check which one `adapters/quinled-dig-uno` holds.
- Matching surprises to resolve: Adapters "QuinLED-Dig-Uno" r33 pairs by URL
  with `adapters/quinled-dig-quad`; Pixels `sm1616` is name-only in both.

### Conversion losses (systematic)

- The CSV export carries **no hyperlinks and no notes**, so every link whose
  target differs from its text and every cell note was lost: ~204 links and
  91 notes are missing from YAML. Biggest groups: Advatek "Pixel Protocol
  Overview" pages (55; YAML kept only the link _title_ in `other_links`),
  datasheet/product links on name cells (~60), maker homepages (~26),
  connector pictures (43, → stream 5).
- Numbers were taken at **display precision**: prices `$15.99` → 16 (≈40
  rows), 18.5 mA → 19, 5.1 V → 5 etc. ("rounded" in the report).
- Diffusive Materials ratings typed as `3-4` became dates in Sheets (shown
  `m-d`); the CSV showed `3-4`, so YAML is fine, but the sheet's raw values
  are dates.

### Values dropped by later bulk migrations

- Flat→nested controller migration dropped `max_pixels` where per-output
  capacity wasn't stated (20 controllers now show no capacity at all); the
  nested schema has only `outputs.pixels.max_per_output`.
- Sheet "Outputs" (Single / Single or Clock = configurable pins / Single and
  Clock = dedicated clock pins) folded into `outputs.clocked`; the
  configurable-vs-dedicated distinction survives only in YAML comments.

### Sheet-side errors inherited by YAML

- A run of controllers sorted by price (F16V4 … Octo Mk2) all read "FPP,
  Ethernet/Wifi" in Interface: looks like a fill-down accident; DiGidot,
  Genius, etc. got Wi-Fi/FPP from it. Verify per entry.
- "DMX to SPI" name cell links to the ENTTEC DIN-rail page (copy-paste).

## Things not to do

- Don't edit the Google Sheet (read-only audit).
- Don't blindly overwrite YAML with sheet values: many YAML values were
  researched after the sheet copy; resolve conflicts with sources.
- Don't trust sheet names for identity: duplicates, vandalism and mislabels
  are common; match on content and URLs.
